# jzmedia 文档

让读者完成任务并找到唯一可信说明。适用于根 README、用户与开发文档、Android TV、脚本和设计文档；代理指令与开发计划按各自用途维护。

## 确定任务与依据

- 遵循仓库及目标目录的 `AGENTS.md`。以[全仓文档规范](../../../docs/developer/documentation.md)为规则来源，按任务读取内容组织、排版、评审或制作章节；这里的相对链接以本 skill 所在目录为基准，执行命令以仓库根为工作目录。
- 先判断请求是编写/维护还是纯审核，并确定受影响页面。只有用户要求全仓治理时才扩大到全仓；内部重构无文档影响时无需启动文档流程。
- 根据读者和结果区分教程、操作指南、参考、解释。AGENTS、导航和计划不强套教程模板；长流程与短操作按规范选择 Step 或有序列表。
- 用实现、配置、锁文件、脚本帮助和可复现验证核对事实。路线图中的提案不代表已实现能力；遇到旧文与代码不符时记录证据，按当前任务修正或作为审核发现。

## 编写与维护

1. 查找已有正文及引用，确定本次信息的唯一归属。先更新原文，再判断是否需要新页；新增页应服务于独立读者任务。
2. 只改本次任务及必要关联内容。行为变化同步步骤、命令、成功判断和恢复办法；参数细节优先链接到脚本帮助或权威参考。不要把每次开发经过追加到教程。
3. 拆页、改标题或删除内容前检查入链、旧锚点、导航和应用帮助目标。迁移仍有效的独有信息，保留开发约束；未被引用、篇幅长或被 Git 忽略都不是删除依据。
4. 依[排版规则](../../../docs/developer/documentation.md#markdown-排版)审查标题、表格和图文。关键步骤与结论可从正文读到；涉及 Vue 组件时同时核对源 Markdown 和生成 HTML，不以站点渲染正确推断其他阅读器也正确。

代码变更需要同步文档时，从变化的命令、配置、接口或用户操作查找受影响正文，避免无关润色。UI 任务涉及教程截图时，沿用界面验收和隔离素材流程。

## 纯审核

保持被审文件不变；用户同时要求修复时再按编写流程处理。可以进行必要的只读检查和本地构建验证，不执行教程中的真实安装、扫描、整理或发布动作来代替审阅。

按[评审标准](../../../docs/developer/documentation.md#修改后的评审)先检查事实和任务完整性，再检查内容归属、重复、结构与排版。按影响排序输出“位置、问题、读者影响、依据、建议”，区分必须修复的错误、风格建议和未验证项；未发现问题就直接说明覆盖范围，不凑问题或生成独立审核报告。

## 验证与交付

- 根据[构建与检查](../../../docs/developer/documentation.md#构建与检查)选择验证范围。局部文字修改先做相关链接与正文检查；公开页面、导航或构建相关变更使用完整验证；主题、组件和交互变更再增加浏览器检查。先核对实际工具入口，不运行尚未实现的计划命令。
- 复用仓库工具，不把检查脚本复制进 skill。Android TV 的日常命令与设备验证遵循其[工程约束](../../../android-tv/AGENTS.md)；同步交付镜像与 APK 时遵循[统一发布](../../../docs/developer/releasing.md)，不要把单端构建当作已完成双端发行。
- 新页面是否发布由公开清单决定；计划与私有记录保持原边界。图文素材使用隔离演示与合成媒体，不为文档验证修改真实片库；生成物从源更新。
- 说明本次修改或审核发现、实际执行的检查及未覆盖范围。只有核对内容后才更新 `reviewed`；构建或模拟通过不能代替新手试读、外部服务或真机验收。

维护本 skill 时只增加能改变执行决策的规则；详细标准继续更新到开发文档，重复遗漏优先用现有检查工具约束。调整触发描述或流程后，用实际的编写、纯审核和无需文档修改的请求复核行为。
