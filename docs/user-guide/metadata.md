# 扫描与元数据

[用户手册](README.md)

## 扫描、匹配、落盘

扫描发现文件并更新库记录；匹配关联电影/剧集资料；落盘按视频库策略写 NFO/图片；归档整理才移动或重命名。入口有媒体库“扫描全部视频库”、视频库行扫描，以及“设置 → 媒体库工具”的第一步。先检查库在线、类型和路径，再扫描、阅读任务摘要、在第二步处理未匹配/待确认/疑似英文/未归属花絮或集号问题，最后按需要预览第三步整理。取消任务只停止后续处理；已入库项仍在。普通增量扫描复用已有匹配，来源规则变化才考虑强制重扫。

## 文件名与候选

清晰的标题和年份提高电影匹配率；剧集支持常见季集号、多集范围与部分绝对号。样片、花絮分流，隐藏/系统目录及 BDMV/VIDEO_TS 等原盘碎片会跳过或单独处理。短标题、重名作品、不同播出顺序仍需要人工核对；即使年份接近也可能只是待确认。额外忽略目录可用 `SCAN_SKIP_DIRS` 配置。

电影入口为详情“编辑 → 手动匹配”；剧集入口在剧详情。搜索候选后核对标题、年份、海报和来源再绑定。换绑会影响后续简介、海报及整理名；仅修改显示标题不能修复错配。正确绑定后若 NAS 上仍是旧 NFO/海报，查看落盘策略与权限，再使用“重写元数据”。

## 来源链与离线资料

| 来源 | 用途 | 注意 |
|---|---|---|
| 本地索引/缓存 | 复用历史匹配、导入与来源资料 | 只覆盖已有信息 |
| NFO | 读媒体旁资料和本地图片，可离线入库 | 文件必须与媒体归属正确 |
| TMDB | 电影/剧集元数据与图片 | 需凭据和网络 |
| Wikidata | 无 key 外源及标识桥接 | 字段覆盖不保证完整 |
| TVmaze | 剧集及部分分集资料 | 分季/编号要和本地核对 |
| Bangumi (`bgm`) | 动漫等候选来源 | 建议配置 User-Agent，结果仍需核对 |
| IMDb 数据集 | 扩充离线标题、年份和 ID 索引 | 不等于完整海报/简介来源 |
| 豆瓣候选 | 默认关闭的可选提示源 | 不是完整豆瓣刮削/评分服务 |

“设置 → TMDB 配置 → 元数据降级链”选择视频库、勾选来源并保存。默认链为 local → tmdb → wikidata。按链顺序找候选，并非合并所有来源字段。连续失败的来源会冷却，查看最近错误、修复网络后再重置；正常空结果不算失败。没有 TMDB Token 仍可用 NFO、缓存和部分外源，但外源本身可能要联网。

## NFO 与图片

现有电影 NFO 放在影片目录或与文件同名，剧集资料放在 `tvshow.nfo`、季/集对应位置，扫描可导入支持字段和本地图片。先用少量样本检查混放目录和多版本归属。导入和写回方向不同：`none` 不主动写 NFO/图片，只读库也不允许落盘。

电影独占目录通常共用 `movie.nfo`、`poster.jpg`；同片多版本默认共用目录资料，Plex 命名档且 edition 不同才补每版本资料。不同影片混放目录按文件同名资料处理。`PER_VERSION_META=1` 可回退旧行为。剧集重建工具可重写 NFO/海报。图片缓存位于数据目录，媒体目录落盘是另一份。

日常纠错顺序：核对绑定 → 核对落盘设置及写权限 → 单片刷新/重写 → 最后预览整理；不要靠改文件名掩盖错配。
