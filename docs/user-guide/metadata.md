# 扫描与元数据

[用户手册](README.md)

扫描发现文件并更新库记录，匹配把文件关联到电影或剧集资料，落盘按视频库策略写 NFO 与图片，归档整理才移动或重命名。四件事入口不同，不要混为一谈。

<DocDiagram src="../assets/diagrams/ingestion.svg" alt="扫描发现文件，匹配确定作品，按策略写资料，整理需另行确认" caption="扫描入库与移动改名是不同步骤。" />

<span id="案例一一次顺利的入库"></span>

## 案例一：一次顺利的入库

以电影 `大桥下面 (1984).mkv` 为例，文件放在某个电影视频库的 `大桥下面 (1984)/` 目录下：

1. 到「设置 → 扫描与整理」选择该电影视频库，在第 ① 步点「扫描新文件」。若已启用的资料来源找到可靠候选，任务摘要会显示新增 1 部并完成匹配；未匹配或待确认时进入第二步核对。
2. 海报墙出现《大桥下面 (1984)》，详情有简介、演职员与海报；媒体目录多出 `movie.nfo` 与 `poster.jpg`（取决于该库的落盘策略）。
3. 点播放验证能播。结束：不需要再做整理，文件名本来就是规范的。

能自动匹配是因为文件名带清晰标题与年份。短标题、重名作品、不同播出顺序仍要人工核对；即使年份接近，也可能只是标为待确认。

<span id="案例二发现匹配错了"></span>

## 案例二：发现匹配错了

假设某部国产片被绑到了同名外国片上，症状是详情的简介、海报与实际内容对不上。按顺序做三件不同的事：

1. **纠正匹配**：详情「更多操作 → 重新匹配」，输入正确标题与年份，核对候选的标题、年份与来源后绑定。「编辑资料」中的简介覆盖、评分和标签不会改变作品绑定，不能用它修正错配。
2. **核对资料**：先检查换绑后的简介与图片；确需重新获取时，点「更多操作 → 更新资料」，按新绑定刷新，并按库策略重写 NFO/海报。
3. **写回文件**：若媒体目录里还是旧 NFO/海报，先看该库落盘策略与写权限，再用「更多操作 → 修复资料文件」，选只修 NFO、只修海报或两者。

<DocFigure src="../assets/screenshots/rematch-candidates.webp" alt="重新匹配候选的标题、年份与来源" caption="演示环境：输入正确标题后搜索，核对标题、年份与来源再点“绑定”；换绑不会移动文件。" />

日常纠错顺序固定为：核对绑定 → 核对落盘设置及写权限 → 单片刷新/重写 → 最后才预览整理。不要靠改文件名掩盖错配。

未匹配的电影或整部剧会先显示简短提示；点击“匹配资料”才展开搜索表单。已匹配但资料错误时，继续使用“更多操作”中的重新匹配入口。打开表单本身不会改绑定或移动文件。

### 辅助核对匹配

启用[智能辅助](settings.md#智能辅助)后，按以下步骤获取并核对建议：

1. 打开电影或剧集的“匹配资料”或重新匹配表单，点击“AI 匹配建议”。
2. 核对实际片名、年份、来源与内容，点击“选择此候选”。
3. 再次核对后，点击“确认绑定此候选”。名称和年份相近仍可能是另一部作品；已存年份与文件名线索冲突时会提示，需人工核对。

系统同时保留原片名和模型整理的查询词，按当前条目所属视频库配置的资料来源查找真实候选，再由模型辅助排序并说明理由。

获取建议不会更改影片绑定、写入 NFO 或移动视频。只有选中候选并明确确认后，才进入原有匹配流程；该流程可能按视频库策略更新资料文件。没有合适候选时继续手动搜索，模型不会凭空创建正式影片资料，也不会仅凭自己给出的置信度自动绑定。

<DocFigure src="../assets/screenshots/ai-match-movie.webp" alt="电影 AI 匹配建议列出候选来源与原因，选中后显示确认绑定按钮" caption="v0.19.0，2026-10-03：模拟片名、候选与模型说明，真实页面展示两步确认；未连接真实资料源或模型服务。" />

如果已查到真实候选，但模型排序失败，仍会列出候选并标注“尚未完成 AI 核对”，可按标题和年份手动判断。无法绑定的候选会显示原因：只有索引线索时继续手动搜索；剧集已有目录归属而候选是其他作品时，需到“归属与季号”预览并调整。取消等待仅停止当前页面等待，已经发出的调用可能仍计入用量。

剧集建议只帮助核对整部剧；季号、集号和已确认的目录归属仍按[剧集匹配](tv-matching.md)与[归属与季号](tv-bindings.md)处理。

## 入库整理的三个步骤

「设置 → 扫描与整理 → 对应视频库 → 入库整理」分三步，默认展开有待办的那一步：

1. **扫描入库**：读新影片并匹配资料，同时移除文件已不存在的记录。普通增量扫描复用已有匹配；来源规则变化才考虑强制重扫。取消只停止后续处理，已入库项保留。
2. **核对匹配**：处理未匹配、待确认、疑似英文、未归属花絮或集号问题。进入电影或剧详情，未匹配时点「匹配资料」；已有匹配需要纠正时，在「更多操作」中选择重新匹配。
3. **目录整理**：预览原路径与目标路径，确认后才改名或移动。见[整理章节](organizing.md)。

## 来源链与离线资料

| 来源 | 用途 | 注意 |
|---|---|---|
| 本地索引/缓存 | 复用历史匹配、导入与来源资料 | 只覆盖已有信息 |
| NFO | 读媒体旁资料和本地图片，可离线入库 | 文件必须与媒体归属正确 |
| TMDB | 电影/剧集元数据与图片 | 需凭据和网络 |
| Wikidata | 无 key 外源及标识桥接 | 字段覆盖不保证完整 |
| TVmaze | 剧集及部分分集资料 | 分季/编号要和本地核对 |
| Bangumi (`bgm`) | 动漫等候选来源 | 建议配置 User-Agent，结果仍需核对 |
| IMDb 数据集 | 扩充离线标题、年份和 ID 索引 | 不等于完整海报/简介来源 |
| 豆瓣候选 | 默认关闭的可选提示源 | 不是完整豆瓣刮削/评分服务 |

默认链为 local → tmdb → wikidata，按链顺序找候选，并非合并所有来源字段。没有 TMDB Token 仍可用 NFO、缓存和部分外源，但外源本身可能要联网。在[匹配规则](settings.md#匹配规则)中按视频库选择来源、调整优先级和测试已保存规则；TMDB 凭据与全局运行状态在[在线资料服务](settings.md#在线资料服务)，IMDb 导入在[离线资料](settings.md#离线资料)。

## NFO 与图片

电影 NFO 放在影片目录（`movie.nfo`）或与文件同名；剧集用剧根 `tvshow.nfo`、季目录 `season.nfo`、分集同名 `.nfo`。扫描可导入支持字段和本地图片，先用少量样本检查混放目录和多版本归属。

电影独占目录通常共用 `movie.nfo`、`poster.jpg`；同片多版本默认共用目录资料，只有 Plex 命名档且版本 edition 不同才补每版本资料。不同影片混放的目录按文件同名资料处理。需要兼容旧多版本资料策略时参见[配置参考](../getting-started/configuration.md)。图片缓存在数据目录 `posters/`，媒体目录落盘的是另一份；落盘开关是视频库的 `none/nfo/nfo_art` 策略，只读库不写盘。
