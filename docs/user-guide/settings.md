# 设置与维护

[用户手册](README.md)

## 设置页的范围

“设置”有全局区和“媒体库工具”。全局区提供库状态、媒体库建连、TMDB、访问控制、显示和搜索索引；库工具以**每个视频库一个标签页**。多个媒体库时标签带媒体库名。打开某部电影/剧集的“去设置”深链会尽量定位到对应视频库、步骤或更多工具。

库工具按入库流程分三步：电影为扫描 → 待匹配确认 → 归档整理；剧集为扫描 → 剧集匹配/集号待处理 → 目录整理。默认展开当前最需要处理的步骤，手动切换后不会强行抢回。低频或影响文件的功能在“更多工具”。

## TMDB、外源与访问令牌

“TMDB 配置”输入 Read Token（优先于 API Key）或 API Key、运行时代理、语言及图片源，点“保存并测试”。设置页可查看生效来源，空输入并不一定清除已有数据库值；使用“恢复跟随 .env”返回环境配置。元数据来源链按视频库勾选；连续失败的来源冷却后应先修复原因再重置。[来源说明](metadata.md)。

“访问控制”配置可选令牌。配置后 `/api` 的 POST/PUT/PATCH/DELETE 需令牌，浏览和媒体 GET/直链仍开放；它不提供用户账号、按库权限或完整公网访问控制。令牌存设置时优先于环境变量。[部署配置](../getting-started/configuration.md)。

## 显示与索引

“显示”可调字体大小和海报墙密度，提供恢复默认。“搜索索引 / 离线数据”有全局 FTS 重建：搜索结果与资料不一致时可使用，不会下载元数据。IMDb 数据导入需要服务端可读的数据集路径；容器部署时要先挂载，任务有进度/取消。

## 电影视频库维护

入口：“设置 → 媒体库工具 → 电影视频库 → 更多工具 → 高级维护”。除特别说明外，操作只作用于当前标签的视频库。普通扫描、匹配和单片刷新能解决的问题，不必先做整库维护。

| 操作 | 适用情况与实际影响 |
| --- | --- |
| 补产地信息 | 从现有 TMDB 缓存补齐缺失的产地及人物关联；不重新请求 TMDB，也不写 NFO。没有缓存的影片需先刷新来源。 |
| 刷新全部 TMDB 数据 | 逐部请求远端资料，处理当前视频库内已绑定 TMDB 的影片；执行数量受任务上限约束。会更新来源数据，手工标题保留。网络或代理有问题时先修复连接。 |
| 重建全部 NFO | 按当前影片资料和目录规则重写 NFO；可能清除历史遗留的同名 NFO。用于换机或 NFO 丢失后修复，先确认视频库可写。 |
| 重建元数据（NFO+海报） | 从已有匹配与镜像缓存离线重写 NFO、海报/背景图；远程库会写入 NAS，任务可查看进度并取消。适合资料已正确但目录产物缺失的情况。 |
| 清理 BDMV 碎片 | 移除误当电影入库的蓝光目录碎片**数据库记录**，保留物理文件。 |
| 清理误入库样片 | 移除样片/花絮被误当电影入库的**数据库记录**，保留物理文件。 |
| 清理挂载残留 | 仅对远程库显示；预览并删除**未挂载的本地挂载点**中历史误写的 NFO/图片。真正挂载中的 NAS 目录不参与。 |
| 清理转码缓存 | 预览后清理 `data/transcode` 中可回收的会话与预缓存产物，跳过在播会话；**范围是全局**，不受当前视频库标签限制。海报和 NFO 不受影响。 |

清理项先看预览清单，再二次确认。详情页“重写元数据”只针对当前影片，适合换绑后资料未落盘时先试。清理 BDMV/样片记录后再次扫描是否入库，取决于当前扫描识别规则和实际文件路径。

电影“恢复到原始位置”使用首次入库路径；“文件浏览”可处理目录内文件。缩略图批量生成在维护面板内，生成范围为当前视频库。

## 剧集视频库维护

入口：“设置 → 媒体库工具 → 剧集视频库 → 更多工具 → 剧集维护”。“剧集刮削（未匹配/未刮）”补齐尚缺的剧/季/集资料；“强制重刮”重新取得已刮资料。两者更新数据库与 `data/posters`，不改视频文件或 NAS 目录。绝对集号映射可能仍需人工检查，尤其是特典、DVD 顺序或分季版本。

“预览写入清单”可先看重建剧集 NFO/海报的范围。执行后会向媒体目录写 `tvshow.nfo`、季 NFO；视频库选用“NFO+海报”模式时还会写海报及背景图，不会改名或移动视频。远程库默认不写逐集 NFO；启用 `TV_EPISODE_NFO=1` 会增加大量远程写入，请先评估库的规模。批量预览缩略图也是当前视频库范围。剧集整理和撤销在第三步，不由维护工具代替日常匹配。

## 任务进度与取消

扫描、预缓存、批量预览和若干维护项以后台任务显示进度。点取消是协作式停止后续工作，已成功的文件或记录通常保留。重启服务后部分进程内任务状态消失；重新进入页面先检查实际结果，再决定是否重跑。尽量避免在同一视频库并行执行扫描、强制重刮、整理和删除。
