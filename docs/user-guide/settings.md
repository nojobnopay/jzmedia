# 设置与维护

[用户手册](README.md)

按任务跳转：[连接资料服务](#在线资料服务) · [调整匹配规则](#匹配规则) · [配置智能辅助](#智能辅助) · [维护电影库](#电影视频库维护) · [维护剧集库](#剧集视频库维护)。首次使用请先看[添加第一部影片](onboarding.md)。

## 设置页的范围

设置页按侧栏切换内容，一次只显示一个分区。桌面按“媒体管理 / 资料与智能 / 系统设置”分组，手机在顶部“设置分类”下拉选择器中切换，旁边保留“新手配置”。分区标题旁标明作用范围，操作前先确认是全部媒体库、选中的视频库还是当前浏览器。

<DocFigure src="../assets/screenshots/settings-navigation.webp" alt="设置概览：分类导航与库统计" caption="按任务选择分区：查看库状态、连接存储、扫描整理、管理文件，或配置资料服务和智能辅助。" />

| 分组 | 分区 | 用途 |
| --- | --- | --- |
| 媒体管理 | 概览 | 库统计、待办与存储使用情况 |
| 媒体管理 | 媒体库连接 | 添加存储位置、检查连接、管理电影库与剧集库 |
| 媒体管理 | 扫描与整理 | 选择视频库，进入入库整理、资料维护或电影还原位置 |
| 媒体管理 | 文件管理 | 按视频库浏览与管理文件，变更后扫描核对 |
| 资料与智能 | [在线资料服务](#在线资料服务) | TMDB 连接与来源状态 |
| 资料与智能 | [匹配规则](#匹配规则) | 按库选择来源、排序与测试 |
| 资料与智能 | [智能辅助](#智能辅助) | 模型配置、智能搜索与匹配建议 |

| 系统设置 | 界面显示 | 当前浏览器的字体、海报大小和剧集更新推荐 |

| 系统设置 | 系统维护 | 全局搜索索引重建与播放缓存清理 |

概览优先显示“需要处理”，点击待办会定位到对应视频库；下方分别查看电影与剧集统计。存储使用情况按需展开，也可从快捷入口进入媒体库连接或扫描与整理。

### 确认作用范围

- **整个实例**：在线资料凭据、智能辅助、离线资料、访问令牌与系统维护，各浏览器共用。
- **对应的库**：媒体库连接、视频库增删改及匹配规则，各浏览器共用；扫描与整理只操作当前选中的视频库。
- **当前浏览器**：字体、海报大小、剧集更新推荐与忽略的系列推荐，保存在当前浏览器。

### 在扫描与文件管理之间切换

“扫描与整理”每个视频库一个标签。入库整理分为扫描 → 核对匹配 → 目录整理，默认展开有待办的步骤。电影和剧集工具分别显示；详细说明按需展开。文件浏览与修改有独立的“文件管理”入口。已打开的工具面板和任务进度会保留；配置草稿按下方离开提醒处理。电影/剧集详情页的原有链接仍会定位到对应视频库和工具。

需要查看或修改源文件时，点击工具栏的“管理文件”，会进入独立文件管理并保持视频库范围。通过此入口打开后，可用“返回扫描与整理”回到原工具标签和步骤；刷新文件管理页后仍可返回。文件可直接在弹窗中预览，视频预览不记录观看进度。[文件管理说明](files.md#原地预览文件)。

## 未保存修改与离开提醒

编辑 TMDB、智能辅助、匹配规则、访问令牌或媒体库/视频库表单后，切换设置分区或离开设置页会提示尚未保存的项目：

- **继续编辑**：保留输入，返回对应表单后再点击保存。
- **放弃修改并离开**：丢弃草稿并离开，不会自动提交配置。

<DocFigure src="../assets/screenshots/settings-unsaved.webp" alt="设置尚未保存对话框列出草稿，并提供继续编辑与放弃修改并离开" caption="先确认提示中的表单或视频库。继续编辑保留草稿，放弃后恢复已保存配置。" />

保存失败时输入仍保留；保存或连接操作进行中，需要等待完成后再离开。等待弹窗打开期间保存成功，会关闭弹窗并留在原页，此时可再次切换页面。刷新或关闭标签页时使用浏览器自己的离开提醒，具体文案由浏览器决定。草稿只保留在当前页面内，强制关闭浏览器或进程可能使它丢失。

字体、海报大小与剧集更新推荐即时保存到当前浏览器，不需要再确认。匹配规则切换视频库时保留各库草稿，离开该分区时统一列出。文件管理产生的实际文件变更仍由原有扫描核对提醒处理，不会因放弃设置草稿而撤销文件操作。

## 在线资料服务

1. 打开“设置 → 在线资料服务”，填写 Read Token（优先于 API Key）。
2. 需要 API Key、语言、代理或图片地址时，展开“API Key、代理与其他配置”。
3. 点击“保存并测试 TMDB 连接”，查看按钮下的结果；只需保存时点“保存配置”。

密钥留空表示保留；清空代理等配置会恢复服务器环境配置或默认值。配置来源在折叠区显示，“恢复服务器配置”需再次确认。

<DocFigure src="../assets/screenshots/settings-sources.webp" alt="在线资料服务设置" caption="尚未配置凭据的在线资料服务：填写后可保存并测试 TMDB 连接，下方查看来源运行状态。" />

“凭据已配置”仅说明已有凭据；“保存配置”的成功提示也不表示已经联网验证。“保存并测试 TMDB 连接”使用保存后的有效凭据和服务器代理，直接验证 TMDB API，在按钮下显示结果或凭据无效、超时等原因；通过不代表海报下载也已验证。

连续失败的来源会暂停使用，正常空结果不算失败。在“来源运行状态”查看错误，修好网络后点“立即允许重试”。此运行状态在所有视频库之间共享。[来源能力与离线范围](metadata.md#来源链与离线资料)。

### 剧集播出资料维护

“在线资料服务 → 剧集播出资料”检查全部启用的剧集视频库中已经确认 TMDB 匹配的剧。配置有效凭据后，服务器先完成一次全库基线检查；同一 TMDB 作品跨库复用检查结果。之后连载等未结束剧集每 7 天检查，已完结或已取消剧集每 90 天检查。服务器会在后台维护这些资料，不需要保持网页打开；首次检查只将近期播出内容列为新集候选，不会把多年以前的内容全部推荐一遍。

面板显示“可检查剧集、已有资料、待检查、检查失败”数量及上次/下次检查时间。点击“立即检查播出资料”提交检查，排队或执行时显示进度状态；离开设置分区后后台任务继续，再打开面板可读取当前状态。未匹配或匹配待确认的剧不会计入可检查数量。

失败时保留上次资料并显示原因，修正凭据或网络后可再次检查；限流与失败冷却期间不会因反复点击而连续请求。“刷新状态”只读取当前进度。此功能不扫描媒体、不更改季集编号、不写 NFO 或海报到媒体目录。单部剧也可在[剧详情](watch-tv.md#查看连载状态与缺季)点击“检查更新”。

## 匹配规则

1. 在“设置 → 匹配规则”选择视频库，勾选需要的来源，至少保留一个。
2. 用“上移 / 下移”调整优先级。新勾选的来源排在末尾；查找按顺序进行，找到候选后停止。
3. 点击“保存匹配规则”，使当前视频库的规则生效。“恢复默认选择”只更新草稿，仍需保存。
4. 输入片名，点击“测试已保存规则”，核对候选数、实际来源和耗时。

切换视频库会保留各库草稿，并提示未保存的库数量；可点“放弃本库修改”恢复该库已保存规则。离开匹配规则分区或设置页时会列出尚未保存的库；先逐库保存需要保留的修改，或明确放弃后离开。

“测试当前视频库匹配”按库类型搜索电影或剧集，使用该库已保存的来源顺序，不会绑定或修改媒体资料。修改规则后需先保存才能测试。空结果会提示“未找到候选”，不能据此判断连接正常；使用备用来源找到候选也不能证明 TMDB 本身连通。

<DocFigure src="../assets/screenshots/settings-matching.webp" alt="匹配规则：按库选择来源、调整优先级和测试" caption="各库独立保存来源顺序；切库保留草稿。图中已把 TMDB 移到首位并保存，下方可测试当前视频库的已保存规则；示例使用模拟 API。" />

## 离线资料

在“设置 → 离线资料”导入 IMDb 标题数据。导入需要服务器可读的数据集路径；容器部署时要先挂载，并填写容器内路径。任务有进度和取消入口。导入内容供全部视频库共用，在需要的库的“匹配规则”中启用“本地索引”即可参与查找。

<DocFigure src="../assets/screenshots/settings-offline.webp" alt="离线资料独立分区" caption="离线资料导入与在线连接、匹配规则分开。示例为模拟数据，未执行导入。" />

## 访问保护

“访问保护”配置可选令牌。保存新令牌后，所有 `/api` 的 POST、PUT、PATCH、DELETE 请求都需令牌；浏览列表和读取媒体直链等 GET 请求仍开放。网页播放器的播放决策、会话建立和进度保存使用 POST，首次调用时也可能要求输入令牌，不能将此设置当作完整的媒体访问限制。

空输入不会关闭保护。“移除已保存令牌”会先显示确认：若服务器仍配置了令牌则恢复使用，否则关闭保护；由服务器直接提供的令牌需在服务器移除。它不提供用户账号、按库权限或完整公网访问控制。[部署配置](../getting-started/configuration.md)。

## 智能辅助

入口：“设置 → 智能辅助”。默认关闭，关闭时服务字段收起，点击“配置与测试服务”可先配置并测试。可选择 DeepSeek、OpenCode Go 或自定义兼容 Chat Completions 的服务，填写 API 基础地址、模型名称和 API Key。设置由服务器保存，整个实例共用；浏览器只显示密钥尾号，不会取回完整密钥。

### Step 1：选择服务并填写配置

| 服务商 | 选择后预填的 API 地址 | 模型示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-flash` |
| OpenCode Go | `https://opencode.ai/zen/go/v1` | `glm-5.3-flash` |
| 自定义兼容接口 | 保留当前地址，按服务商要求修改 | 填写该接口支持的模型 ID |

选择服务后检查地址、模型，并填写对应的 API Key。这里只保存一套当前配置；切换服务商不会分别保管各家的密钥，Key 留空仍沿用现有值，因此切换后应填写对应服务的 Key。再次打开页面会保留已保存的模型，不会重新套用示例。

API 基础地址填写到接口根目录，不包含 `/chat/completions`；例如 DeepSeek 的 `https://api.deepseek.com`，或本地兼容服务的 `http://localhost:11434/v1`。本地地址由 jzmedia 服务器访问，容器中的 `localhost` 指容器自身。

OpenCode Go 的模型 ID 直接填写 `glm-5.3-flash` 这类名称，不加 `opencode-go/` 前缀。只选择官方列为 `/chat/completions` 的模型；本版不支持 Go 的 `/messages` 或 `/responses` 模型。模型清单会变化，以[官方接口表](https://opencode.ai/docs/go/#endpoints)为准。

2026-10-03 核对时，Go 官方仍要求客户端发送典型的编程代理请求；jzmedia 的影视搜索与匹配用途尚未完成真实服务验证，不能保证订阅和 Key 可用于此场景。详见[官方使用范围](https://opencode.ai/docs/go/#where-can-i-use-it)。被拒绝时检查凭据、订阅及服务商的用途要求，仍可改用 DeepSeek 或其他兼容服务。

<DocFigure src="../assets/screenshots/ai-settings-go.webp" alt="智能辅助设置中选择 OpenCode Go，显示预填地址、模型和用途提示" caption="v0.19.0，2026-10-03：真实设置界面配合模拟 API，无真实 Key。图中测试结果仅演示交互，不代表 OpenCode Go 已连通。" />

### Step 2：保存并测试连接

点击“保存智能辅助配置”后，再点“测试已保存连接”。可以先测试连接再启用；修改地址、模型或 Key 后要先保存。

**预期结果：**测试显示接口可用。失败时检查对应服务的地址、凭据、订阅和用途要求，修正并保存后重试。连接测试通过不代表所有中文表达或影片候选都能判断正确。

### Step 3：确认发送内容并启用

智能搜索会把输入文字和当前库的可用筛选项发给所选服务；匹配辅助会发送用于辨认作品的名称与真实候选资料，不上传视频。确认服务地址与发送内容后，勾选“启用智能辅助”并保存。

使用步骤见[智能搜索](find-movies.md#智能搜索)和[辅助核对匹配](metadata.md#辅助核对匹配)。智能辅助不会接管普通扫描，建议仍需核对后应用。

### 密钥、限额与停用

API Key 留空表示保留已有值。在“调用限额、超时与密钥管理”中调整每日上限和超时，也可明确移除已保存的 Key。确认移除后，若服务器配置了 `AI_API_KEY`，会恢复使用该环境配置；否则需凭据的服务将不可用。自定义兼容服务可按其要求使用空 Key。需要停止调用时取消“启用智能辅助”并保存，不能仅凭清空输入框判断已停用。

页面显示当日调用次数，“查看用量说明”可展开 Token 用量和计数规则。每日调用上限按 UTC 日期计数，UTC 零点相当于北京时间上午 8 点。连接测试和实际发往模型的请求都会计次，失败请求也计次；命中本地 AI 结果缓存不重复计次。一次匹配建议可能分别解析片名、排序候选，最多使用两次模型调用。Token 用量按服务返回的使用量统计，不是账单金额；服务商费用仍以其账单为准。达到调用上限后仍可使用普通搜索与手动匹配。

制作教程或体验页面无需真实模型 Key，可使用[无 Key 演示与截图](../developer/documentation.md#智能辅助的无-key-演示与截图)；该演示中的解析、候选和连接结果均为固定模拟数据。

## 界面显示与系统维护

“界面显示”调整字体和海报大小，修改后自动保存到当前浏览器；海报越小，每行越多，可一键恢复默认。

“剧集更新推荐”默认“每周提醒一次”，可改为“关闭推荐”。它控制当前浏览器的剧集海报墙，不改变服务器检查播出资料的周期，也不隐藏剧详情中的状态、缺季和分集目录。每周推荐只列近期已播但尚未收藏的分集，不弹出对话框。[查看推荐与收藏范围](watch-tv.md#海报墙的每周推荐)。

手机会根据屏幕宽度和海报大小偏好自动调整列数。默认海报大小下，360～430 像素宽的手机视口通常为三列，320 像素窄屏为两列；调大海报后每行可能减少。字体大小单独设置，放大后文字和操作区会按可用空间换行。

“系统维护 → 搜索索引”用于修复搜索结果与资料不一致，不会下载元数据。“播放缓存”先检查可清理空间，再明确确认删除；作用于全部媒体库，跳过正在播放的会话。清理后再次播放可能需要重新缓存，海报和 NFO 不受影响。

## 电影视频库维护

入口：“设置 → 扫描与整理 → 电影视频库 → 资料维护”。除特别说明外，操作只作用于当前标签的视频库。普通扫描、匹配和单片刷新能解决的问题，不必先做整库维护。

| 操作 | 主要用途 |
| --- | --- |
| 补全产地与人物 | 从现有缓存补齐缺失关联 |
| 更新本库影片资料 | 重新从 TMDB 获取资料 |
| 修复资料文件 | 向媒体目录写入 NFO 或图片 |
| 移除蓝光碎片记录 | 清理误入库的数据库记录 |
| 移除样片与花絮误入库记录 | 清理误入库的数据库记录 |
| 清理挂载残留 | 清理未挂载的本地挂载点 |

### 补全或更新资料

“补全产地与人物”只使用现有 TMDB 缓存，不重新请求 TMDB，也不写 NFO；没有缓存的影片需先刷新来源。

“更新本库影片资料”经确认后逐部请求 TMDB，每次最多处理当前视频库内 5000 部已绑定 TMDB 的影片。来源数据会更新，手工标题保留；网络或代理有问题时先修复连接。

### 修复 NFO 与海报

选择仅 NFO、仅海报或两者，确认目标和写权限后执行。工具按当前资料与镜像缓存写入，保留库的落盘策略；远程库会写入 NAS。修复海报或两者时有后台进度与取消入口。

详情页“修复资料文件”只针对当前影片，适合换绑后资料未落盘时先试。

### 清理误入库与挂载残留

移除蓝光碎片、样片与花絮误入库项只删除**数据库记录**，保留物理文件。再次扫描是否入库，取决于当前扫描识别规则和实际文件路径。

“清理挂载残留”仅对远程库显示；确认后删除**未挂载的本地挂载点**中历史误写的 NFO/图片，真正挂载中的 NAS 目录不参与。

清理项收在“清理误入库记录与挂载残留”，操作前会说明影响，再次确认后执行。

其他任务见[电影还原位置](organizing.md#完成后检查)、[文件管理](files.md#文件浏览器)和[批量生成进度缩略图](playback-previews.md#操作步骤)。

## 剧集视频库维护

入口：“设置 → 扫描与整理 → 剧集视频库 → 资料维护”。“补全缺失剧集资料”补齐尚缺的剧/季/集资料；“重新获取全部剧集资料”重新取得已刮资料。两者更新数据库与 `data/posters`，不改视频文件或 NAS 目录。绝对集号映射可能仍需人工检查，尤其是特典、DVD 顺序或分季版本。

<DocFigure src="../assets/screenshots/tv-maint.webp" alt="剧集资料维护面板" caption="剧集维护：补全/重取资料、重写剧集 NFO 与海报（可先预览写入清单）、批量生成进度缩略图。" />

“预览写入清单”可先看范围，再点“重写剧集 NFO 与海报”。执行后会向媒体目录写 `tvshow.nfo`、季 NFO；视频库选用“NFO+海报”模式时还会写海报及背景图，不会改名或移动视频。远程库默认不写逐集 NFO；需要启用时请维护者参考[配置说明](../getting-started/configuration.md)，并评估大量远程写入。批量预览缩略图也是当前视频库范围。剧集整理和撤销在第三步，不由维护工具代替日常匹配。

## 任务进度与取消

扫描、预缓存、批量预览和若干维护项以后台任务显示进度。点取消是协作式停止后续工作，已成功的文件或记录通常保留。重启服务后部分进程内任务状态消失；重新进入页面先检查实际结果，再决定是否重跑。尽量避免在同一视频库并行执行扫描、强制重刮、整理和删除。
