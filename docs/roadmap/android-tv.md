# Android TV 状态与发布

本页维护当前验收状态与影响交付的限制，不进入公开帮助站。构建、安装见 [README](../../android-tv/README.md)，操作检查见[测试指南](../../android-tv/docs/testing.md)，打包规则见[发布指南](../../android-tv/docs/releasing.md)。

连接、浏览、搜索、播放和独立会话已实现。当前版本以根 [version.properties](../../version.properties) 为准，与 Docker 镜像统一发布；协议仍为 1。

## 在线点播 P4

P4 已接入原生在线页面、可选能力握手与独立 Media3 在线播放。2026-10-28 的搜索与播放基础实现已通过 JVM、工具、Android Lint 和 Debug／Release 本地构建检查；此前本地媒体、P5、ASS、观看模式和覆盖安装的真机反馈不扩大为在线流程已验收。已提供 `0.33.0-debug`／code 58 开发测试包，包含在线浏览、详情布局及离线拼音键盘；测试包不代表统一公开发行或已完成设备验收。

电视通过 `features` 中的 `online_vod` 判断服务器能力，不猜最低版本号；缺失时隐藏在线入口，儿童模式同样隐藏并拒绝直达。来源显式声明目录能力时自动浏览，支持来源分类快捷行、按能力提供的年份筛选、单源搜索及各自分页；旧服务端未声明目录能力时保留搜索。详情使用同源海报及紧凑操作区，线路与分集网格支持长目录分组、倒序及不可播放原因。收藏、历史、按精确身份续播和被动来源状态沿用在线接口。浏览条件、查询、结果和焦点仅存于当前观看身份的内存，详情返回恢复原条目与位置。在线收藏和断点属于本电视、当前模式；与本地媒体的全家共享进度分开，不承诺网页／电视账户同步。

独立播放器仅接受稳定身份及同源原时间轴 `passthrough` 描述，由电视解码 MP4/HLS；MP4 串联不超过 8 MiB 的有界 Range，不新增 NAS 解码、转码、重封装、字幕烧录或预览。默认关闭的自动连播只在真实结束后进入同源同线紧邻下一集，不支持就停止，不跳集。关闭、Home、待机、连接／模式／权限变化需要停止声音并释放本机会话，旧请求不能重新起播或覆盖新进度。

自动检查与隔离合成媒体按[在线测试流程](../../android-tv/docs/testing.md#验证在线点播)进行；新的目录筛选和详情布局、离线拼音候选输入与焦点、长剧分组／倒序、翻页及返回焦点，以及原生 Media3 首帧、长文件跨区间读取、音轨／字幕、续播、连播与退出清理仍需设备证据，物理电视的解码、声画及家庭网络另验。在线总体阶段见[视频源计划](online-video-sources.md#p4-的实施拆分)。

## F1 P5 保留原视频播放已通过真机确认

APK 已按当前 P5 片源的规格查询原生杜比硬件解码器与显示能力，通过后请求保留原视频；实际选中轨道仍需通过杜比格式及解码能力检查。服务端及新版 APK 的旧服务端守卫均阻止 P5 回落普通视频转码。接口和数据库结构保持兼容，P7 不随此功能放宽。

2026-10-18，用户确认已安装的 `0.29.0-debug`／code 45 在其红米电视以“原视频”播放《F1：狂飙飞车》，连续播放 30 分钟、前后跳转、切换音轨和字幕，以及退出后无残留声音均通过。依据为用户实际使用反馈，仅对应该电视、片源和已安装试装包。

本次未另附解码器日志、量化色彩、逐帧跳转精度及 100ms 音画同步目标的测量结果；新版 APK 的实际安装回归与其他片源仍按[P5 检查流程](../../android-tv/docs/testing.md#验证-dolby-vision-p5-原生播放)验证，不扩大为所有 P5／P7 支持或 NAS 网页 P5 转色验收。能力策略、服务端决策和旧服务端计划保护由本地自动检查覆盖；Media3 杜比配置解析设备测试已编译，尚未运行。

## 影响安装与发布的限制

**正式签名 APK 交付：维护者发布准备，按需启动。** 当前统一发行交付固定签名的 Debug 试装包；本机统一发布入口已支持正式签名构建，正式 Release 交付与升级尚待验证。历史 Debug 覆盖升级的验收按上一节收尾。

按[正式 Release 步骤](../../android-tv/docs/releasing.md#正式-release-的额外步骤)完成以下工作：

1. 维护者在仓库外准备并备份正式密钥，使用统一发布入口生成正式签名 APK，核对证书、源码与校验记录。采用云端正式发行时，先补齐当前仅交付 Debug 的工作流。
2. 明确最低兼容服务端发行版本，在测试设备验证正式包首次安装、启动、连接及基本播放；连接兼容性继续以[协议握手](../../android-tv/docs/protocol.md)判断。
3. 有前一正式版本后，验证同密钥、更高版本覆盖安装保留连接配置与偏好，并记录结果。首次正式安装和后续正式升级分别记录状态。

Debug 与 Release 使用不同应用标识，可并存且不共享连接配置；正式包首次安装按独立应用验证。维护者负责密钥、构建与校验，需要设备配合时提供明确的安装包和操作步骤。

## 验收记录要求

每项验收记录 APK/服务端版本、设备/API、操作、结果与证据。模拟 API、真实后端合成媒体、软件模拟器、物理电视分开记录，不为验证操作真实媒体的扫描、整理或删除。长期跨端布局证据见[设计验收清单](../../design/acceptance/2026-10-03.json)；旧版本测试计数和修复过程保留在 Git 历史，不再逐轮追加。
