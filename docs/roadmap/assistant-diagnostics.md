# 小映诊断与配置建议开发计划

第一项应用是网页端在线视频播放。用户可以从播放器、浏览页或设置里问「为什么量子资源播不了？」。目标是用服务端取得的证据回答，必要时只确认一次，复测后报告实际恢复到哪一步。

## 第一期 · 本机诊断、确认和复测

1. 将播放故障识别为只读诊断，保留当前来源、影片、线路、分集和可识别的错误类别。没有唯一来源时请用户选择。继续使用已有观看模式、设备作用域和管理授权。
2. 按检测结果组织工具。读取 API 与媒体观察，按该来源当前的出口现场检查目录；有节目上下文时核对详情和可安全访问的清单或少量媒体数据。记录每项检查的对象、结果和依据。启用模型时可在提供的只读工具中选择下一步，未配置模型时也能走本地流程。
3. 必须有旧地址失败、同运营方候选经同一出口验证可用的证据才生成换址提案。区分单集故障、缺少已允许的主机、设备解码、代理与来源不可达。发现证据不足时说明缺少的观测。
4. 提案列出来源、新旧接口、允许列表变动与对正在播放会话的影响。将提案绑定当前设备授权、来源、网络版本和有效期。「同意」与按钮走同一条有冲突检查的写入路径。成功后保留原来源身份，使用已经保存的配置复测。重复提交返回已有结果。

## 第二期 · 可溯源网页与工具组合

1. 为已识别的运营方注册采集帮助中心，按已核对的页面结构提取标明用途的 JSON 接口。网页证据带出处、栏目和读取时间；解析失败时说明采用随版本收录的候选。
2. 运营方公布的地址仍需从本机验证。网页文本、聊天文字和模型输出均不能直接扩展允许列表或写入配置。读取网页与检测接口沿用现有网络策略，约束可访问主机、读取大小、耗时和请求次数。
3. 让工具选择与配置写入独立。模型只选择当次可执行的工具，程序负责校验参数、运行检查和归纳证据；管理授权和数据版本由服务端在确认时复核。后续增加元数据或扫描工具可以复用选择机制。
4. 用代理出口上的媒体失败验证组合能力。用户允许临时直连后，用同一分集比对两个出口。只有直读取样成功才提议把此来源的「视频播放」改为直连，并保留其它用途的规则。

## 验收

| 场景 | 应得到的结果 |
|---|---|
| 旧目录无法使用，可信候选返回有效节目 | 显示出处与验证结果；确认一次才保存；复测原节目或说明仅验证到目录 |
| 目录正常，单集清单失败，或客户端解码失败 | 报告对应环节，保持来源配置 |
| 公告改版、发布页不可达、候选返回 HTML、代理限流 | 分别报告事实与本地模板回退；证据不足时没有可提交的换址操作 |
| 两个同名来源、当前故障与历史观察不同 | 选择具体来源，优先使用当前分集和新取得的证据 |
| 重复确认、提案过期、授权变化、另一管理员改了来源或出口 | 重复请求不重复写入；失效的提案要求重新诊断 |
| 首段可取，终端未回报首帧 | 回执只说明服务器已验证的范围，用户可重试原分集 |

使用受控网页和网络响应、临时数据库及桌面与手机浏览器验收。真实部署核验只读页面、健康状态、镜像内容与业务数据，用户自己的来源留给实际试用。

## 已实现与验证方式

- 网页端在在线浏览、在线设置和播放器提供同一个诊断入口。服务端为本轮读取设置约 28 秒时限。配置提案在五分钟内有效，刷新服务后需要重新诊断。
- 目录换址只替换经过本次检测的 API 主机。逐项选择媒体、海报域名仍使用设置里的换址预览。复测回执区分「已保存」「已读到目录」「已读到原线路媒体样本」，最后一步的设备播放由用户重试。
- 网页读取已接入量子、暴风和非凡的帮助中心。其它来源可以诊断已配置的目录和播放线路。增加新的运营方或工具，需要注册来源、定义可验证的数据，并补上测试。
- 后端回归覆盖真实解析与受控响应、提案的并发和授权，以及缓存与远程播放的区分。浏览器冒烟在临时片库中实际走过输入确认、按钮确认、过期配置冲突与保存后复测。[后端诊断用例](../../tests/test_online_diagnostics.py) · [确认用例](../../tests/test_assistant_online_diagnosis.py) · [浏览器验收脚本](../../scripts/smoke_assistant_source_migration.mjs)
- 播放器与详情页的浏览器验收使用同一合成剧集，核对诊断请求的集数和线路，分别触发临时直连、保存和重新播放，并验证新会话的播放时间开始推进。[播放器验收脚本](../../scripts/smoke_assistant_player_diagnosis.mjs)

用户入口和例句见[请小映诊断播放问题](../user-guide/watch-online.md#online-source-diagnosis)。
