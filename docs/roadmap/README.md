## 维护规则

- 新项写明当前代码缺口、预计范围和验收条件；未经确定不承诺发布日期。
- 完成后同步现行说明，标记“已完成”并简要列出实现与验证依据；不复制阶段性长报告。未测环境与未完成子项继续明确列出。
- 核对代码、测试与实际证据后再更新状态，不按旧台账或日期判断功能是否完成。构建和模拟器通过不能代替真机验收。
- 真实使用反馈可按明确的媒体库、设备和操作范围收尾；未记录的格式或专项不推断通过。回归清单按变更或问题触发，不把所有未使用环境列为必做待办。
- 没有实际问题支撑、收益低于开发和维护成本的候选直接删除；以后出现具体需求再评估，不另建低价值需求归档。
