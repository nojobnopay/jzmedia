# 在线视频源调研与开发计划

建议为 jzmedia 增加独立的在线点播能力，让用户搜索、选择并播放 NAS 中不存在的电影和剧集。技术上可行，现有播放器可以复用；主要新增工作是视频源适配、在线内容身份、受控取流和失败恢复。

当前状态：**P0–P3 已完成开发机隔离验收；网页已具备来源配置、搜索播放、收藏、持久续播、连续播放与最近请求状态。P4 电视原生接入通过工程自动检查，设备播放与遥控验收待完成。** MacCMS JSON 和需要显式启用的 Big Buck Bunny 开放样例已连接现有设备会话与有界透传网关；客户端仍只提交稳定身份，不提交播放 URL。免费来源继续优先应用层直连，尚未交付默认中文影视片库。此前约 21 分钟单路、TS 双路各 5 分钟证据保留，原始 30 分钟目标未补写为通过。调研及实现日期为 **2026-10-26 至 2026-10-28**；物理电视与生产环境验收仍待后续，此计划不进入公开帮助站。

首期建议采用 **MacCMS JSON 直链适配 + HTTP(S) MP4/HLS 点播 + 独立在线入口**。按用户 2026-10-26 补充要求，优先选择在实际部署网络中无需出站代理、可稳定播放的免费来源，并为不同服务分别配置网络。源协议是否兼容、接口是否免费、内容是否允许接入、能否稳定直连，需要分别验证。开源聚合程序不等于附带免费片库。

同日新增负载约束：**NAS 能力较弱，新增在线流程的音视频解码优先由浏览器、手机或电视等实际播放设备承担；NAS 以目录/API 请求、鉴权、播放地址解析和有界媒体转发为主。** 首期不自动启动服务端解码、转码、字幕烧录或全片分析，长播验收以终端实际播放为准。

[CatVod 开发说明](https://github.com/FongMi/CatVodSpider/blob/main/docs/development.md)区分搜索、详情和播放解析；播放标识可能需要运行脚本才能变成 URL。兼容这类源还需要宿主 API、依赖与隔离执行环境，不适合放进首次点播迭代。

### 本地源码核对与采用决定

用户授权后，已将下列仓库浅克隆至本机忽略目录 `output/research/online-sources/20261026/`。仅静态阅读，未安装依赖、运行或部署第三方项目；`manifest.json` 记录完整提交及许可，项目分析 JSON 保存文件指纹和证据位置。

| 固定版本 | 源码确认的主路径 | 对 jzmedia 的采用决定 |
| --- | --- | --- |
| LibreTV `29cbeb3`，2.21.1 | MacCMS → 原始 HLS URL → 浏览器；网络错误后提示并自动尝试同源转发 | 参考分层和有限错误恢复；路径由显式策略决定，不无提示更换出站代理 |
| LunaTV `6c0428d` | 服务端查 MacCMS，浏览器直接拉点播 HLS；直播另有转发接口 | 参考客户端测试与清理；保留各线路身份，不只取集数最多的一组 |
| Stremio SDK `ec4e0a4` | catalog/meta/stream JSON 返回内容及播放描述，能力取决于客户端 | 参考稳定内容 ID 与临时 URL 分离；首版只采用 HTTP(S) 范围 |

LibreTV 的[播放器](https://github.com/LibreSpark/LibreTV/blob/29cbeb3d37b4876f909a0354087a3531af0447f6/src/components/player-shell.tsx#L342)直接调用 hls.js 加载来源，网络失败后自动尝试一次同源 `/api/proxy`；[恢复决策器](https://github.com/LibreSpark/LibreTV/blob/29cbeb3d37b4876f909a0354087a3531af0447f6/src/lib/playback-recovery.ts#L42)区分网络、媒体及不可恢复错误。所查链路未调用服务端 FFmpeg。它的同源代理默认整响应超时约 8 秒，不能直接用于长 MP4；[缓存默认值](https://github.com/LibreSpark/LibreTV/blob/29cbeb3d37b4876f909a0354087a3531af0447f6/src/lib/video-cache.ts#L24)会预取数百秒、占用较多客户端空间，经 NAS 转发时也会消耗其带宽，因此不采用这些默认值。

LunaTV 的[点播播放器](https://github.com/MoonTechLab/LunaTV/blob/6c0428d1ae7a8322efa8031909ec77cac22fd866/src/app/play/page.tsx#L1337)使用浏览器 HLS，worker 承担 hls.js 处理，音视频解码由浏览器媒体栈完成。其[MacCMS 解析](https://github.com/MoonTechLab/LunaTV/blob/6c0428d1ae7a8322efa8031909ec77cac22fd866/src/lib/downstream.ts#L239)按 `.m3u8` 结尾筛选，可能漏掉带查询串的清单；直播代理的来源参数传递、Range 与背压处理也不足以直接作为 jzmedia 网关。两项目中的广告删片、无限恢复或大型预取均不纳入首期。

Stremio 的[播放描述](https://github.com/Stremio/stremio-addon-sdk/blob/ec4e0a49e61bac4f2285891d39414dfbafe93f58/docs/api/responses/stream.md#L34)区分客户端兼容性及所需请求头；[SDK 路由](https://github.com/Stremio/stremio-addon-sdk/blob/ec4e0a49e61bac4f2285891d39414dfbafe93f58/src/getRouter.js#L50)返回 JSON。它不是免费内容来源，也不能把 `proxyHeaders` 当作每服务的出站代理设置。

这次核对确定了 P0 的验证调整：优先补真实 HLS 的主/子清单、音轨、初始化段、分片及终端播放；分别记录客户端直接取流和 NAS 透传结果。保留真实连续播放的门槛，并把 MP4/CDN 的失败作为独立兼容与来源结果。LibreTV 的 AGPL、LunaTV 的非商业及相同方式共享许可与本项目不同；此处参考公开协议后独立实现，不复制它们的播放器或代理代码。

## 免费源选择

### 来源目录与浏览体验

网页新增来源目录，提供开放样例以及暴风、量子、非凡的配置模板；用户选择后预填地址与精确允许主机，新增来源默认启用，在线总开关仍由管理员控制。目录不自动添加、访问或更新所有候选。2026-10-29 开发机有界核实仅暴风目录 API 直连读取通过，量子与非凡仍待当前网络验证；这些结果不证明媒体、整片或 NAS 可用。具体步骤与来源状态集中在[在线观看](../user-guide/watch-online.md)。

连接设置以直连或填写 HTTP(S) 代理为主，原有六用途规则保留在高级设置，已有 API 与媒体例外不会静默重置。在线首页自动浏览当前来源最近更新，使用实际来源分类和同源海报墙；“发现推荐”表示来源更新发现，不提供虚构的个性化排行。图片同样经过来源、观看权限及独立网络用途校验，只做有界字节读取，不给 NAS 增加解码或媒体处理。

慢源优化将开放末尾 MP4 Range 窗口缩短为 1 MiB，显式范围仍最多 8 MiB；保持请求期限、并发和总流量限制。开发机 BBB 吞吐存在波动，不能据单次对比把卡顿归结为必须代理；长于 8 MiB 的限速合成片用于验证浏览器自然续取，真实部署网络和声画体验仍需分开验收。

首期不依赖付费订阅、收费解析服务或商业云账户。采取“明确来源的小规模开放片库 + 管理员配置的免费 API”两条路径，既验证技术，也检验实际内容价值。

在内容许可和功能满足需求的候选中，按网络要求排序：**免费且全链路稳定直连 → 免费且视频直连、仅 API 或辅助资源需要代理 → 免费但视频必须走代理**。未测来源先标为“待验证”，不得按国内域名或项目所在 GitHub 仓库推断可直连。代理需求和排序根据部署网络实测更新；仅代理可用的来源作为备选，不成为首版默认依赖。

同等网络条件下，优先提供目标设备可直接解码的编码、封装和清晰度的来源。某一路不兼容时先换上游线路或已有清晰度，不把 NAS 重编码作为自动兜底；降低分辨率只有在上游提供该版本时才不需要服务端重编码。

| 候选来源 | 用途与优先级 | 尚需验证 |
| --- | --- | --- |
| 用户配置的免费 MacCMS JSON 接口 | 首期优先寻找 API 与媒体均可直连的来源 | 使用条件、内容范围、API/CDN 直连、限流与失效情况 |
| Blender 开放影片，如 Big Buck Bunny | P2 显式启用的固定样例；开发机有界直连读取通过 | 目标部署网络、实际播放设备和长期稳定性 |
| Internet Archive 中逐项核实许可的公开影片 | 可选适配；若依赖代理，优先级后移 | 内容许可、API/文件直连、Range 与播放稳定性 |
| 由频道发布者提供的免费直播，辅以 iptv-org 发现 | 后续扩展，优先稳定直连频道 | 订阅下载与实际流分别验证、地区限制、长期可用性 |

Big Buck Bunny 的[发布者说明](https://peach.blender.org/about/)标明原 Peach 项目采用 CC BY 3.0，适合作为许可可追溯的样例。P0 通过 Blender 官方 PeerTube 找到了实际 MP4，开发机和 NAS 的有限 Range 读取均成功；早期浏览器播放和跳转通过，但该轮未清除环境代理，不能据此认定直连播放已通过。HLS 自动回归使用本地合成片源；真实网络与终端播放另用 Apple 官方测试流验证，测试流不作为产品片库。

首批内容方案确定为“显式启用的开放样例目录 + 管理员配置的 MacCMS 接口”，而不是默认附带商业影视片库。BBB 详情需展示影片名、Blender Foundation、原项目与许可链接，并保留完整片尾署名。PeerTube 两条 API 的 `Attribution` 标签没有许可版本，不能自动把讲座或目标 60fps 文件都标成 CC BY 3.0。中文候选的许可未确认，继续不内置；开放样例不能代表主流中文电影、剧集或新片覆盖目标已经达成。

Internet Archive 的[官方元数据 API](https://archive.org/developers/md-read.html)提供条目和文件清单，可用于实现轻量适配器；仅选择已核实可以接入的公开文件，不将站内全部内容视为同一种许可。其覆盖内容与主流中文新片需求可能差距较大，需要在 P0 记录用户关心的内容覆盖情况。

MacCMS 是接口形式，不是一个统一的视频提供商。首期只接受详情接口直接返回可播放 MP4/HLS 的来源；搜索能返回标题但只提供网页、解析 ID 或不可用地址，应显示“当前源不支持播放”，不能算作接入成功。豆瓣、TMDB 等元数据也不能当作播放源。

本次未找到足以承诺“长期稳定、免费且覆盖主流新片”的统一来源。已找到的项目证明聚合接入方案可行，具体免费来源仍须逐个验收。首期只提供显式启用的开放样例，其余通过管理员配置；最近实际请求状态由 P3 的进程内观察提供，不把有界读取成功直接当作整片可播放。

P0 已分别实测部分 API 和媒体地址，结果如下。源码仓库、订阅列表、搜索 API、封面站点和视频 CDN 可能使用不同地址；访问项目主页成功不能证明视频可直连，访问某个页面失败也不足以证明必须使用代理。

## 在线发现体验优化

本节以 **2026-10-29 核对的暴风资源能力**定义网页交互。U1 的图片缓存与浏览恢复、U2 的分层分类与资料、U3 的关联发现，以及 U4 的详情与长列表选集已完成开发机隔离验收。沿用[来源官方接入说明](https://bfzy.tv/helps/)及[公开目录接口](https://bfzyapi.com/api.php/provide/vod/?ac=list)，通过限量 API 请求核对实际行为，不套用其他 MacCMS 站点的能力。

### 来源能力与界面边界

| 能力 | 当前暴风样本 | 界面采用方式 |
| --- | --- | --- |
| 分类层级 | `class` 有 49 类、9 个根类及 `type_pid`；都市脑洞 `71` 属于短剧 `58` | 一级频道收拢二级分类，保留来源 ID |

年份筛选已有正负例，但接口没有返回完整可选年份枚举；界面提供近年选项及手动年份入口，不用当前页已有年份冒充全目录选项。样本中的搜索附加字段 `work_id`、`group_key` 按单作品变化，`detail` 也是单作品定位，不能当系列关系使用。部分短剧缺演员、导演、标签及豆瓣资料；也存在同名第二季分属喜剧片和欧美动漫两个 ID 的情况。未核对来源前台网站的推荐实现，以上结论只覆盖其公开采集 API。

同日补验“发现”页不指定分类的年份查询：`year=1900` 无结果，`year=2026` 首批 20 项均为 2026 年。两次直连请求仅读取公开元数据，共 67,128 字节，未读取视频；记录位于本机 `output/diagnostics/online-u2-20261029/live-year-check.json`。

U2 已保留分类父 ID、更新备注及有界的题材、地区、语言、演员、导演等资料；缺失或不合适的可选字段为空，不影响原本可播放的条目。年份只对精确匹配已核对暴风接口及默认详情动作的来源声明支持，其他来源不显示控件并拒绝非空年份请求。内容类别与播放 `kind` 分开，补资料不改变已有内容身份、收藏和进度。

### 海报加载与返回体验

优化前的应用侧原因是：每次进入重新读取来源及目录，海报仅缓存 URL 凭据而没有图片内容；响应 `no-store` 导致网格重建时重新请求；图片全局两路读取，排队也计入单张 10 秒期限；分类在详情列表不带 `class` 时还会重复请求。图片失败与加载中也不易区分。

开发机直连小样本中，两张 WebP 仅 8,810 / 15,616 字节，读取约 0.700 / 0.292 秒，同图再次读取约 0.248 秒。该测量复用了探测客户端连接，只覆盖一个图片域名，不能作为现有网关端到端耗时，也不能证明截图中所有空白都由超时造成。当前证据不支持把问题归结为必须配置代理。

U1 已实现以下改动，保持 NAS 只处理有界元数据与图片字节：

1. **复用图片内容。** 增加最多 16 MiB、512 条、单图最多 512 KiB、10 分钟有效期的服务端内存 LRU，同图并发合并读取；不落盘、不缩放、不解码。缓存按来源、完整网络及来源配置指纹和规范 URL 隔离。命中仍验证当前观看权限、来源开关、配置和图片凭据，受保护响应继续 `no-store`。

### 同系列与相关推荐

关联查询在详情及当前条目状态读取完成后延迟启动，独立请求且只查当前来源。一次冷查询最多 8 秒、3 次元数据请求：目标详情、一页根片名搜索与按需一页具体分类；合计最多 12 张候选，不抓全目录、不为每张卡再请求详情。成功结果按观看身份、保护代次及完整来源和网络配置在进程内缓存 120 秒，最多 32 条、2 MiB；命中仍复核权限、配置并重新登记海报租约，不保存永久系列表。

推荐沿用每进程 4 路、每观看身份 1 路的目录限额，全进程最多一路后台推荐。播放或主动查询可取消推荐，并在其实际工作退出后优先接管名额；最多 4 个抢占等待者，等待计入各自原期限，不提前释放仍在工作的配额。忙碌或被抢占的推荐返回暂缓，界面只提供手动继续；超时与错误只在推荐区提示，不自动循环重试。换片、换线路、返回、离开及观看权限变化会取消旧结果。

- **同系列优先。** 只移除明确的“第几季”等季标记，保留具有区分意义的正文和版本信息；同根名、明确季号及相容内容类别是基础。年份、地区、演员等有值时辅助判断，明显的作品身份或版本冲突则排除，资料缺失时提高片名规则要求。不同季年份不同、演员阵容变化不单独否定同系列。按季序显示，缺季保持缺失，不推测不存在的第一季。
- **保守关联。** 同名不同类别或版本保留独立条目和来源标识，不只凭去掉数字后的片名合并作品。无季号、短名称缺额外佐证、同季多个独立版本等低置信候选放在“名称相关”，不附“同系列”标签；季切换通过稳定 ID 打开详情并更新深链，不自动播放、换源或跨季连播。返回保留原分类、年份、页码和位置。
- **一般推荐。** 系列结果不足时，可复用当前具体分类的有界结果；已有候选中的题材、演员等资料只用于轻量排序。标签标明“同系列”“同类型”等实际理由，空评分不显示。没有候选就隐藏推荐区，不虚构榜单，也不为此要求用户配置 TMDB。

若其他来源以后返回非空关联 ID，需验证其语义和目标身份后作为候选信号；不能直接信任外部 URL 或据此跳过观看权限。已有收藏、续播和分集身份保持独立，推荐不会把多个季写成一个播放条目。

### 真实播放与稳定性

Blender 官方条目 `6402b77c-b61f-4a06-96ca-c8420a2becf4`（Big Buck Bunny，约 634 秒）和 `8e364d32-8918-403e-a8c0-915634b9f405`（Scientific Visualization Panel，约 5242 秒）在 API 中标为 Attribution 且允许下载。本次选用各自 360p MP4，不扩大为整站许可判断。

早期开发机 Chromium 使用 `--no-proxy-server`：两部视频均有真实解码帧和时间推进，分别跳转至 120 秒和 600 秒后继续播放；完整短检查分别约 8.5 秒和 12.6 秒。首轮达到“时间超过 2 秒且已有画面”的观测约 5.3 秒和 8.1 秒，不当作精确首帧时间。该轮保留了测试进程的代理环境变量，证据不足以证明无代理播放；也不能反过来断言实际经过代理。此结果不代表 NAS 浏览器、电视或人工声画验收。

NAS 应用容器对长讲座执行低优先级、单线程、无媒体落盘的 30 分钟直接读取解码测试，**实际仅完成约 202 秒媒体时间，墙钟约 293 秒**，出现连接重置、partial file 和 AAC 解码错误。FFmpeg 返回 0，但目标时长未达到且存在输入错误，明确判为未通过。诊断进程已结束，正式容器仍为原启动时间和 healthy 状态。

这项诊断发生在新增负载约束之前，保留为历史证据，不再将 NAS 持续解码设为 P0 通过条件。它也不能证明实际播放设备会同样失败，或把连接重置归因于 NAS 算力不足。

补充诊断发现该长 MP4 开头的 `moov` 索引约 4 MB；有限 Range、开放末端 Range 和 Lavf User-Agent 都能读取首段，因此不能归因为 CDN 一概拒绝 FFmpeg。大索引可能增加起播读取时间，但断流根因尚未确认。

晚间的浏览器对照明确移除 Node/Chromium 继承的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 等变量，保留 `--no-proxy-server`；NAS HTTPX 使用 `trust_env=False`。两条路径分别为终端直接读取官方 MP4，以及“官方 MP4 → NAS 临时有界透传 → Tailscale → 开发机 Chromium 解码”。临时服务使用随机令牌、回环绑定、两请求并发上限、256 MiB 总请求预算及自动退出，不接入正式应用。NAS 的 SSH 转发不可用，改用已存在的 Tailscale 用户态网络，没有修改 SSH 或网络配置。

原长讲座两路均未在 90 秒内起播；NAS 转发约 852 KB，客户端直连记录一次连接重置。另一条官方 Attribution 长片 [BLENDER IS EASY…](https://video.blender.org/api/v1/videos/1200a046-1b1e-4ffc-9145-e2618dbbf3b9) 长 2020 秒、360p 文件约 50.7 MB，索引降至约 1.49 MiB，仍未在 90 秒内起播，NAS 路径记录两次上游读取错误。两轮均未进入 30 分钟计时；不能将未起播描述为通过长播，也不能只凭这些指标定位到源站、出口或 Tailscale 中的某一环节。

同一小索引文件将 Range 上限从 4 MiB 显式改为 512 KiB 后，NAS 完整转发了两个响应、共 1 MiB，未记录上游错误，但仍未在 90 秒内起播。它证明浏览器可以继续请求下一段，不能证明缩小 Range 修复了稳定性。另一次 NAS 显式代理有界对照中，BBB 元数据连接失败，长讲座元数据成功但两个 MP4 Range 连接超时；当前也不能承诺“打开代理即可解决”。上述测试不自动更换出口或扩大等待时间来覆盖失败。

### HLS 续验

2026-10-26 根据开源项目实际使用的 HLS 路径，补充 [Apple 官方样例](https://developer.apple.com/streaming/examples/)与 [hls.js 官方测试流清单](https://github.com/video-dev/hls.js/blob/master/tests/test-streams.js)中的真实网络样本。采用 Apple 的 `bipbop_adv_example_hevc` 中最低 AVC/AAC 变体验证分离音轨及 fMP4 初始化段，另用 [Apple 文档所列](https://developer.apple.com/documentation/applenewsformat/video)的 `bipbop_4x3` 验证 TS 点播。样例只用于诊断，不进入开放影片目录或正式片库。

Apple 主清单允许跨域，但实测子清单缺少跨域响应头，浏览器直接请求失败；NAS 应用层直连能读取这些资源，同源转发后起播成功。Mux 样例的清单可读但媒体传输过慢，未通过 90 秒起播。这些差异说明应分别记录清单可读、媒体吞吐和终端可播，不能仅凭一个 HTTP 200 决定来源优先级。

两种 Apple 封装均通过单路 30 秒播放及独立跳转；TS 样例另通过两路各 30 秒及跳转。双路采用一个 Chromium 的两个独立 context，真实产生两套媒体请求和解码，不能表述为两台真机。该次 NAS 共完成 22 个请求、转发约 5.03 MiB，最高 2 个并发上游请求，错误、拒绝、重试、媒体磁盘写入均为 0，关闭后活动请求和队列为 0。开发机仍保持 2 GiB、2 核、128 任务和无 swap 限制，峰值 105 个任务，无限额命中。

诊断保留了失败与修正依据：初版 HLS 恢复会尝试其他档位，导致请求突发；固定本次变体并增加有界排队后通过。双独立 Chromium 的一次解码初始化失败未取得线程限额证据，不能归因为 NAS 并发能力不足；后续改用共享浏览器的独立上下文。两路长播尝试中，一路首帧前触发起始时间戳空洞恢复，被严格判据拒绝；另一路完成下述观察，不能将该轮标成双路长播通过。

用户认为约 20 分钟已足以作为本轮观察，要求尽快结束并次日继续，因此在实际播放 **1277.738 秒（21 分 18 秒）**时发送 SIGINT。该路首帧约 302 ms，已解码 38,297 帧、丢帧 0，无 HLS 错误、意外跳转或 HTTP 失败；没有循环、倍速或预先下载整片。NAS 转发进程顺播采样平均 CPU 约为单核的 **0.34%**，RSS 约 **37.4 MiB**，上游错误、重试、限额拒绝、媒体磁盘写入和解码子进程均为 0。这是最低码率 AVC/AAC 的单路观测，不代表高码率容量。

保留原始验收状态：脚本目标仍为 1800 秒，因用户主动结束而返回未通过，没有补写成 30 分钟通过；本轮未执行结束后的 seek。两次指标请求超时不影响实际播放，但使严格 NAS 指标判据未通过。停止瞬间尚有一个在途分片，转发进程关闭时 active/queued 均归零；随后独立核验所有已知诊断 PID 不存在、两个临时端口关闭，生产 v0.31.2 健康且启动时间未变。浏览器和 NAS 临时进程均已退出，没有留后台测试。原始记录位于 `output/playwright/online-p0-hls-nas-two-context-long/`；相关后端合并回归 **117 项通过**，Python 静态检查无错误。

## 建议架构

在线浏览和本地媒体库先分开，复用播放组件与现有权限机制。后续取得可靠的 TMDB 等关联 ID，再合并搜索展示；同名、同年不足以证明是同一版本或同一集。

```text
在线搜索 / 详情 / 分集 / 线路
          ↓
Provider：search → detail → resolve
          ↓
稳定内容身份 + 临时播放描述
          ↓
jzmedia 同源 MP4 / HLS 取流网关
          ↓
网页 hls.js / 原生播放 → 后续 Android Media3
          ↓
实际播放设备负责音视频解码与显示
```

### NAS 负载与客户端播放

本次新增在线能力遵循以下职责划分：

- NAS：来源管理、搜索/详情请求、鉴权、播放地址解析、HLS 清单重写、Range/分片透传和少量进度数据。转发按需读取，限制并发和缓冲，不全片下载后再播放，不为每次播放全量扫描远端文件。
- 播放设备：音视频解码、画面显示、声音输出，以及设备支持的选轨、字幕渲染和清晰度切换。同源转发保持媒体内容，由终端的播放器处理；网关不需要解码。
- 能力匹配：结合终端能力选择上游已有的编码/清晰度。优先硬件解码可用的播放路径，不能仅凭分辨率宣称兼容。不兼容时提示换源、换已有清晰度或改用兼容设备，首期不自动启动 NAS 转码、重封装或字幕烧录。
- 媒体信息：优先利用上游元数据、清单和客户端上报。确需服务端补充时采用有时间、读取字节和并发上限的结构探测，不持续解码、不抽帧生成预览，也不在后台解码整片分析。
- 后续扩展：服务端转码、烧录、缩略图等重处理单独评估，不能因复用本地播放器的回退逻辑而默认启用。开发机生成合成测试素材不属于在线运行时流程。

资源验收同时观察空闲、单路播放和两路播放的 CPU、内存、连接数、带宽及临时磁盘写入，确认取消后回收，并确认在线会话未启动媒体解码/转码任务。先取得目标设备基线，再设限额，不用“只转发”推断零负载。长时间播放、声音、字幕与解码能力以实际终端为准；NAS 仅验证网络转发稳定性和资源上限。

### 提供方与数据模型

P1 第一项建立了 `app/online/models.py`、`app/routers/online.py`、`app/store/online.py` 及 schema 32 身份与配置；P2 的 schema 34 补充 `provider_options`，目录和播放解析才发起上游请求，保存配置仍不访问外网。来源改名或更换同一片库的接口地址保留 ID，分集排序不参与身份；创建/修改经过整体验证后原子保存。配置 GET 同样校验已设置的访问令牌，并叠加现有管理保护。现行说明见[在线数据模型](../developer/data.md#在线来源与稳定身份)、[管理 API](../developer/api.md#在线来源配置)和[播放描述](../developer/playback.md#在线播放描述)；P0 验证代码仍独立位于 `scripts/online_p0/`。

- `online_sources`：已保存提供方类型、显示名称、API 基础地址、启停、优先级与允许主机；仅管理员管理，总开关和新来源均默认关闭。网络规则由独立策略接口管理，代理凭据由网络档案加密保存；P3 增加分用途的实际请求观察，来源上游凭据管理仍待后续接入。
- `online_items`：已按来源、内容类型和提供方稳定 ID 保存独立身份与标题；P3 收藏引用该稳定身份，TMDB 关联和按需资料缓存由后续模块接入，不全量抓取外部片库。
- `online_episodes`：已保存父项、外部稳定 ID、标题、季集号及排序，父项必须是在线剧集；分集外部键由线路名称和集名导出，不按数组序号或 URL 映射身份。线路由稳定 `line_id` 选择，当前重新读取详情取得地址，不新增长期保存播放 URL 的 `online_streams` 表。
- 在线收藏与进度：P3 使用设备与普通／隐私模式隔离的独立表，完整身份包含来源、条目、分集和线路，不复用本地观看记录。首次独立展示；后续聚合继续观看时仍需显式扩展现有查询和权限。
- 播放会话：保存有期限的 URL、必要的上游请求头及过期时间，使用随机会话标识访问。签名 URL 不作为影片 ID，也不写入长期收藏记录。

P2 已实现服务端搜索、详情与按稳定身份重新解析播放地址。MacCMS 支持配置搜索和详情的 `ac` 行为，保留所有线路，明确拒绝重复线路或集名等身份歧义；多线路电影要求明确选择线路，失效分集不能自动换集。它沿用 P1 的 `ResolvedPlayback` 契约和受控客户端，不执行远程脚本；具体边界见[在线提供方与目录](../developer/playback.md#在线提供方与目录)。

搜索采用有上限的并发、单源超时和独立结果状态；某个源变慢不能拖住全部结果。健康检查逐级覆盖 API、详情、解析和少量实际媒体读取，不能只用 HTTP 200 判定可播放。

### 按服务配置网络

P1 第二项已实现 `app/network/`、网络配置管理接口、schema 33 与隔离网络验证。网络档案可重用，但目前只有在线来源接入新策略；现有 TMDB、元数据图片和 AI 客户端的出口保持原实现，后续迁移时逐项保留环境、证书及凭据行为，不能静默改成新默认值。现行参数与边界见[配置参考](../getting-started/configuration.md#在线来源的网络策略)，接口见[在线网络管理](../developer/api.md#在线网络管理)。

有效规则遵循 **来源内用途 → 来源默认 → 应用默认**，只在 `inherit` 时继续回退。应用默认初始为显式 `direct`；指定 `proxy` 必须引用代理档案，失败不自动换成直连。用途包括 API、媒体、图片、字幕和订阅，可表达“来源 API 代理、媒体直连”。部分上游绑定出口 IP，混合策略仍须逐源实测；来源优先级继续优先免费、稳定且全链路直连。

网络档案保存直连/HTTP(S)代理方式、超时、每池连接数与 CA 路径，代理凭据只加密写入，不回显到管理响应、播放描述或运行日志。管理端可解释最终选择层级、档案修订号与配置指纹，但不连接目标。被规则引用的档案不可删除，应用默认、来源规则及引用档案通过同一读事务取快照；修改配置只影响新快照。

客户端显式禁用环境代理继承，单独保留 `SSL_CERT_FILE/SSL_CERT_DIR`；TLS 验证不可关闭。每个客户端拥有独立连接池和固定超时，不自动重试；GET/HEAD 重定向手动处理，最多 5 跳并禁止 HTTPS 降级。小响应最多 2 MiB，流式响应不整片缓冲；会话网关另设单进程聚合并发、字节与 TTL 限额，不能把每池上限当成聚合容量。证书文件在原路径替换未版本化，配置指纹也不能证明物理 CA 材料没有变化。

本机回环 HTTP、转发代理、HTTP/HTTPS CONNECT 与自建证书验证了显式直连不走环境代理、不同用途分流、代理认证不进入原站请求、旧快照继续原出口、独立连接池、代理失败不回退、证书文件/目录及日志脱敏。全部使用临时数据库和隔离目标，不代表公网来源已通过接入验收。

P1 第三项已实现独立的目标、头部策略与固定地址传输。来源精确主机白名单与全部 DNS 公网检查后固定数字 IP，直连核对实际 peer；HTTP/HTTPS 目标经代理时都使用数字 IP CONNECT，代理拒绝目标端口时失败，不转普通转发或直连。代理是管理员信任的设备，不能由 NAS 证实它实际连接的远端 peer。每跳重新授权目标与精确 scheme/host/port 的上游秘密，不保存响应 Cookie，应用令牌与 `jz_viewing` 不得传给上游。完整约束见[在线远程读取](../developer/playback.md#在线远程读取)。

管理解释返回 `local_pinned` 与 `required_per_request`，只说明内部客户端必须执行的策略，不发 DNS 或网络探测。在线工厂从同一数据库快照检查总开关和来源启用状态，现由 MacCMS 提供方与会话网关分别按 API、媒体用途使用；正式网页仍不开放任意 URL 测试或转发入口。P3 的来源观察按来源、用途、完整配置指纹和时间保留在当前进程中，不能把代理成功当作直连成功，也不能把取流成功当作终端已解码。

同源媒体网关、出站代理、`MEDIA_PROXY_HOST` 的 SMB 内部 Range 服务和镜像构建/拉取代理继续分别配置。使用同源网关时，上游仍可完全直连；客户端直接取流也不会自动服从 NAS 的出站策略。

### 取流与安全边界

首版网页和电视默认使用 jzmedia 同源入口，便于处理跨域、上游请求头、会话和权限。网关只允许通过已注册来源解析出的资源，不能开放成任意 URL 代理。

开源项目的浏览器直拉方式作为 P0 对照与后续可选优化，需要单独描述播放交付路径，不能和出站代理混用一个 `proxy` 开关：

| 维度 | 选择与边界 | NAS 负载 |
| --- | --- | --- |
| 交付：客户端取流 | 仅公开、无服务器秘密、跨域及终端兼容已验证的 URL；出口由播放设备决定 | 目录与地址解析为主 |
| 交付：NAS 同源转发 | 服务端保管必要头部，处理清单与分片；实际解码仍在终端 | 有界网络/TLS 转发，无解码 |
| 出站：按服务/用途选网络 | 只控制 NAS 发出的请求，明确 direct/proxy/inherit | 与上面两种交付方式分别配置 |

主清单允许跨域不代表子清单和分片也允许；某一路浏览器直拉失败，不能否定已通过的 NAS 转发路径。客户端取流也不能承诺自动服从 NAS 的出站代理配置。涉及服务器凭据、IP 绑定或电视同源限制的来源保持 NAS 交付。

MP4 需要正确转发 Range、HEAD、Content-Type、长度与取消信号。HLS 需要解析并重写主清单、子清单、音轨、字幕和初始化段 URL，覆盖相对地址、跨 CDN 地址和字节区间；不能用简单字符串替换完成。首期只支持无加密点播 HLS；AES-128、DRM、直播和低延迟扩展分别评估，不将普通 HLS 加密与 DRM 混为一谈。

P1 第三项已提供统一 URL 策略，后续 API、封面、字幕、清单和媒体分片均通过该边界读取，不能自行创建客户端。它只允许精确列出的 HTTP(S) 公网目标，检查全部 DNS 地址并固定实际拨号地址；生产策略没有放宽私网的开关。若未来支持用户自建内网源，需另设明确的管理员配置范围。

上游 Cookie、Authorization、Referer、Origin 通过服务端授权按提供方和精确 origin 限定；跨 origin 不保留前一跳秘密。jzmedia 的登录凭据、观看 Cookie、保护口令及接收器密钥不得转发给上游。请求设置大小、并发、连接和读取时间上限，日志不输出签名查询串和秘密；后续取流网关沿用这些约束。

儿童模式默认不显示未分类的外部内容；P1 会话入口暂时拒绝全部儿童模式在线访问，后续分类与管理员明确允许机制完成后再开放。搜索、封面、详情、播放、收藏和历史应执行一致权限，隐藏按钮不能代替后端校验。当前会话绑定设备观看身份及 generation/保护 revision，即使关闭保护也须先取得设备会话。关闭来源或总开关会停止新解析并撤销活动会话，保留收藏和历史以便恢复。会话、Range、HLS 与单进程资源限额的现行约束见[在线会话与透传限额](../developer/playback.md#在线会话与透传限额)，入口见[在线播放会话](../developer/api.md#在线播放会话)。

### 播放体验与失败处理

首期在线页提供来源标记、搜索、详情、选集、选线路、清晰度、收藏和续播。已过期地址允许有界刷新并恢复原位置；401/403、429、404、连接超时及格式不支持分别显示可理解的结果。失效来源支持停用，不能触发本地媒体删除逻辑。

播放器区分网络重试、起播时间轴对齐和真实解码失败。P0 的 Apple TS 样例曾在首帧前发生小段起始空洞恢复；正式实现需要保留这类客户端事件并限制恢复次数，不能将所有 HLS 非致命事件都直接变成“不支持播放”，也不能以恢复为由自动启动 NAS 转码。验收报告仍明确区分无错误播放、发生恢复的播放与失败，不把跳过的时间算入实际播放时长。

同一线路刷新地址可以恢复位置；换到其他来源时需验证电影版本、集数及片长，不承诺无缝跳转。首期保留手动换源，避免自动切换到错误版本。已有字幕引擎可复用，但首版只承诺已声明且验证过的 WebVTT 等格式，复杂字幕由后续适配确认。

本地媒体播放不依赖在线服务健康。在线功能应有默认关闭的总开关；使用独立的连接、并发和缓存限额，取消播放及时释放上游连接。关闭开关后仍可使用本地库。

## 分阶段实施

以下为一名熟悉仓库的开发者全职实施的工程估算，包含定向测试，不是发布日期承诺。等待来源访问、实际设备验收和额外网站反爬适配的时间未计入。P0 后根据源质量调整后续估算。

| 阶段 | 交付范围 | 估算 |
| --- | --- | --- |
| P0：来源与链路验证 | 优先免费直连来源；终端解码长播，NAS 验证透传及资源占用 | 2–3 人日 |
| P1：基础模型与取流 | 独立身份、按来源/用途网络策略、会话、有界透传网关及访问限制 | 5–8 人日 |
| P2：适配与在线入口 | MacCMS JSON、开放样例目录、搜索/详情/分集、复用播放器 | 4–6 人日 |
| P3：首版完整体验 | 收藏、持久续播、自动连播、手动换源、过期刷新、权限、健康状态与回归 | 4–6 人日 |
| P4：Android TV | 在线入口、遥控选集与播放、进度同步、真机验收 | 4–6 人日 |

计入在线来源的网络策略后，网页可用首版合计约 **15–23 人日**，加电视端约 **19–29 人日**。现有元数据、图片和 AI 服务统一迁移到按服务配置，另预留约 2–4 人日，待逐项核对环境继承与兼容要求后再细化。若 P0 证明 Internet Archive 内容和直连网络适合，再安排约 2–4 人日的专用适配器；它不阻塞基础协议与在线点播首版。

### P0 的完成与来源准入

P0 用于作出协议与来源选择的开发决定。完成以下调查和技术证据后进入 P1；默认内置某个来源另需通过该来源的使用条件和稳定性准入。调研得到“暂不内置”的结论也是有效结果，不以无限寻找稳定免费片库阻塞基础工程：

1. 适合验证的公开 HLS 在明确的交付与出站策略下，由实际终端完成读取和解码播放；覆盖主/子清单、相对分片、音轨/初始化段及跳转，NAS 不承担持续解码。MP4 作为独立协议兼容样本保留成功和失败结果，不将某个 CDN 的 MP4 成功作为所有 HLS 来源的先决条件。
2. 优先调查全链路直连的免费 API，完成候选的搜索、详情、分集和取流检查，记录电影及剧集样本；API 成功不等于媒体可播。对已测候选明确采用、管理员自配或暂缓；需代理的来源作为低优先级备选，不能认定满足首选条件。后续新增候选独立验证。
3. 从实际部署服务的网络环境分别检查 API、封面/字幕、MP4 的 Range、HLS 清单和实际分片；同时记录应用模式及已知宿主机/路由器出口。开发机结果不代替目标服务器结果。
4. 在浏览器、手机或电视等实际播放设备记录首帧时间、连续播放、跳转、失败率、可用地区和测试网络。本轮按用户接受的约 20 分钟量级，以已完成的 1277.738 秒连续播放作为长播观察，保留原始 1800 秒目标未完成的状态，不为补足原定时长重复运行。经过 NAS 时仅进行媒体透传，并记录其 CPU、内存、连接与带宽占用，确认没有解码/转码任务。仅在允许的代理配置下做对照测试，分开记录直连与代理结果；来源默认内置前还需在不同时段复测，单次 P0 不承诺长期稳定。
5. 写明实测内容覆盖、来源使用条件和失败项；不满足实际电影/剧集需求或许可未确认的候选不默认内置，保留管理员自配和后续来源准入。开放样片通过只支持技术可行性，不能表述为免费影视片库已经可交付。

上述条件的当前证据与缺口见“P0 实测与运行”。官方页面访问结果不能代替目标服务器上的取流证据；后续 NAS 仅做有界取流、透传和资源采样，不再用持续解码诊断作为验收门槛，不将公开源写入正式片库或观看进度。

### P1 的实施拆分

以下五项已完成开发机隔离验证，P1 基础协议与网页播放器收口。MacCMS 生产适配及正式在线页面属于 P2。

| 任务 | 交付与验证重点 | 依赖 |
| --- | --- | --- |
| 在线身份与播放描述（已完成） | 独立三表与 schema 32、默认关闭开关、来源管理 API、同源 `passthrough` 描述；不提供实际取流 | P0 收口 |
| 按来源和用途配置网络（已完成） | schema 33、直连/代理档案、五种用途规则、固定快照、CA 与凭据处理、独立有界客户端及回环代理/TLS验证 | 身份与配置契约 |
| 公网目标与头部边界（已完成） | 精确主机、全部 DNS 公网检查、固定数字 IP 拨号、直连 peer 校验、数字 CONNECT、逐跳重定向与精确 origin 头部隔离 | 身份、网络策略 |

### P3 的实施拆分

以下能力已完成开发机隔离回归与浏览器验收；不代替真实设备或生产 NAS 的播放验收。

| 任务 | 实现与验证重点 | 状态 |
|---|---|---|
| 收藏与持久观看状态 | schema 35 三表；设备与普通／隐私模式隔离、分页、停用保留及可清理，不混入本地记录 | 已完成 |
| 有序进度与清理 | 已归属 session claim、revision/seq、冻结 scope token、清历史 epoch 撤销旧写入，首帧后才记历史 | 已完成 |
| 网页续播与连续播放 | 完整身份恢复、约 10 秒合并保存、默认关闭的当前浏览器偏好、真实 ended 后同源同线推进及取消 | 已完成 |
| 来源状态与手动选择 | API／媒体独立的实际请求观察、直连／代理与配置指纹、无额外探测；换线明确选集，不自动跨源搬断点 | 已完成 |

收藏和历史按设备观看 Cookie 的服务端身份归属，普通与隐私模式分别保存，不承诺账户级跨设备同步。来源或总开关停用仍能管理已存记录，儿童模式和锁定状态不显示隐私内容。每设备与模式最多 500 个收藏、1000 条完整身份进度；列表按条目归并、网页每页 20 项。状态写入先绑定已归属的会话，发生旧 writer 或 scope 冲突后不自动重新抢写；清除历史在同事务递增状态命名空间，阻止旧回调恢复刚删除的记录。

自动连播只在真实 ended 后刷新目录，按同一来源、条目和线路选择紧邻下一集；下一集不支持时停止并提示，不跳过集数。不会按接近片尾的比例提前推进，不跨源或另选版本。关闭、换来源、关偏好、权限变化及查询失败均取消旧推进，末集结束停止。源地址刷新与 NAS 负载约束沿用 P1/P2，不新增媒体处理。

健康观察只记录实际查询、完整有界清单或媒体响应，按来源与用途在当前进程中最多保留 512 个结果、30 分钟后过期。读取状态不请求上游、不建 TLS 上下文或解析 DNS；重启及配置变化后旧结果不适用，取消不算来源失败。清单或字节读取成功不能代替终端解码或长期稳定验收。实现边界分别见[在线收藏与进度 API](../developer/api.md#在线收藏与进度)和[在线来源观察](../developer/playback.md#在线来源观察)。

2026-10-28，相关后端 889 项、前端 722 项和正式页面 14 个浏览器场景通过，覆盖收藏刷新保留、按线路续播、设备与模式隔离、旧页写入冲突、停用保留、390/320px 触摸布局及真实 ended 后连续播放和取消。首帧前等待有界的进度资格申请，记录失败仍可播放；有效的新序号写入滚动延长两小时空闲期限，假时钟覆盖累计近六小时保存，不把它当作六小时媒体长播。健康观察故障不影响实际目录结果或媒体字节。验证始终限制为 2 GiB、双核、128 个任务且禁用交换；样片在开发机预先生成，服务阶段没有媒体处理子进程，媒体哈希不变，结束时会话、查询与取流资源归零，本地媒体记录保持空。

浏览器证据来自 Chromium 桌面与手机视口模拟，未扩展为 Safari、真实手机／电视、人工声画、公网来源长期稳定或 NAS 部署验收。P4 另行核对电视端能力与设备身份／进度衔接，不将当前设备 Cookie 状态宣称为账户同步。

### 首版验收条件

- 使用临时数据库及本地模拟提供方验证空结果、重复 ID、分集排序、多线路、超时、限流、签名到期和畸形响应。
- 用合成 MP4/HLS 验证开始、暂停、seek、续播、清晰度、音轨/字幕及主/子清单重写；不支持的加密或协议要明确拒绝。
- 验证回环/私网/IPv6/重定向/DNS 重绑定限制、请求头隔离、会话过期、来源停用、儿童模式与保护权限；两个客户端不能互相结束会话。
- 用隔离 HTTP 服务与代理验证：环境设置代理时显式直连仍不经过代理、不同服务/用途选择不同路径、HLS 子资源与重定向遵循策略、代理故障不静默切换出口、配置变化不混用旧健康结果。测试也覆盖 DNS 解析位置、证书配置及凭据脱敏。
- 浏览器覆盖桌面和手机，并分别验证 hls.js 与可用的原生 HLS 路径；页面关闭后取消请求，不持续占用上游连接。
- 终端不支持编码/封装时验证换源或不支持提示，确认不会自动触发 NAS 解码、转码、字幕烧录或预览生成；NAS 在长播中只承担有界转发，并通过单路/两路资源采样确定限额。
- 原有本地电影、剧集、字幕、断点和投屏做定向回归，在线不可用不影响原功能。根据实际修改运行后端、前端和文档检查。
- 电视阶段按照 `android-tv/AGENTS.md` 与设备测试指南执行；自动化通过不代替真机首帧、声画、遥控、续播和退出清理。

### 后续候选
